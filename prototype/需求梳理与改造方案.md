# 需求梳理与改造方案：把 World Monitor 的能力并入 filter-bubble

> 本文是**方案与需求文档**，不含任何对现有项目文件的修改。
> 配套的可视化原型见 [`prototype/worldmonitor-prototype.html`](worldmonitor-prototype.html)（双击即可打开，断网也能看）。
>
> 调研与实测时间：**2026-10-26**（Asia/Shanghai）。文中的接口成败结论都是**我这次真的发请求打出来的**，不是抄文档。

---

## 0. 一句话结论

你想要的「地图」，在 World Monitor 里不是一个组件，而是一套**图层注册表 + 地理编码 + 收敛判定**的数据管线。
好消息是：**它最核心的那部分和 filter-bubble 现有架构天然契合**——你已经有了「适配器注册表 → 统一入库 → 聚类 → 打分 → 日报」的流水线，缺的只是**地理维度**和**主题维度**这两个字段。
代价是：地图底图、地图引擎、以及「国内外」这个概念，都需要**换一种做法**，不能照搬。

## 1. World Monitor 是什么，和你现在的东西差在哪

| 维度 | World Monitor | filter-bubble（现状） |
|---|---|---|
| 语言/构建 | Vanilla TypeScript + Vite（有构建步骤、有 npm 依赖） | 纯 Python stdlib + 原生 HTML/JS（**无构建、无依赖、断网可用**） |
| 地图 | 双引擎：`globe.gl`+Three.js（3D 地球）、`deck.gl`+MapLibre GL（平面）；底图用 OpenFreeMap / CARTO **免 key 瓦片** | 无 |
| 图层 | **58 个图层**，由**唯一注册表** `src/config/map-layer-definitions.ts` 声明 `key / renderers('svg'|'deck'|'globe') / premium` | 无 |
| 数据源 | 自报 **775 provider / 748 条 feed URL 定义**，10 大域 | **35 个源**（直连 + newsnow 聚合 + AnySearch） |
| 后端 | Vercel Edge + Railway relay + Redis 三层缓存 + Protobuf 契约 | 单机 `app.py` + SQLite + 线程调度 |
| AI | Ollama → OpenRouter → 浏览器 Transformers.js 三级降级 | 主/备用 OpenAI 兼容接口 + token 记账 + 本地规则回退 |
| 许可 | **AGPL-3.0-only**（源码）+ 独立商标政策 | 未声明 |

### 许可这条必须说清楚

AGPL-3.0 的实操含义：

- ✅ **可以**借鉴架构、算法与公式（CII 权重表、1°×1° 收敛算法、图层注册表这个模式），自己重新实现不构成传染；
- ❌ **不要**直接把它的源码文件（哪怕只是 `map-layer-definitions.ts`）复制进你的项目；一旦你把修改版**作为网络服务对外提供**，AGPL 要求你向使用者提供对应源码；
- ⚠️ `World Monitor` 这个名称、Logo、视觉识别**不在 AGPL 授权范围内**，有自己的商标政策，fork 不能白标。

**结论**：本方案所有内容都是「按它的公开文档与公式重写」，不搬代码。这也正好符合 filter-bubble 的「无第三方依赖」原则。

## 2. 哪些功能值得结合（按优先级）

### P0 —— 你明确要的，也是投入产出比最高的

| # | 功能 | 为什么值得做 | 你的项目缺什么 |
|---|---|---|---|
| 1 | **态势地图页** | 把已有的 3090 条新闻从「列表」变成「空间分布」，一眼看出事件聚集在哪 | 需要：地理编码 + 新页面 |
| 2 | **图层目录（注册表模式）** | 新增一个图层只改一处声明，正好复用你现有的 `SOURCES + ADAPTERS` 写法 | 需要：图层元数据表 |
| 3 | **新闻地理编码** | 已有 3090 条标题里，我用一个 90 词的地名库就命中了 42 条（见原型），实际可用 GeoNames 做到 60–80% | 需要：地名库 + 匹配器 |
| 4 | **国内外分主题** | 现有报告是**按平台名硬编码**分栏的（见 §5），加新源不会自动进分栏 | 需要：`region` + `theme` 两个字段 |

### P1 —— 明显加分，且数据免费

| # | 功能 | 说明 |
|---|---|---|
| 5 | **地理收敛告警** | World Monitor 的招牌：1°×1° 网格 + 24h 窗口，同一格出现 ≥3 类信号就告警（`type_score = 类型数×25`）。原型的「地理收敛告警」面板就是这个算法跑在你自己的数据上——实测跑出了「日本（自然+基础设施+新闻，89 分）」等收敛区 |
| 6 | **图层说明卡** | 每层写清楚「用途/来源/接入方式/新鲜度/局限」。这条特别适合你的项目气质——你现有的「诚实标注未接入」就是同一个价值观 |
| 7 | **CII 国家不稳定指数** | 公式完全公开：`eventScore = 不稳定×0.25 + 冲突×0.30 + 社会×0.20 + 信息×0.25`；`composite = baseline×0.4 + eventScore×0.6 + 各类 boost`。可以只用你已有的数据算一个「简化版 CII」 |
| 8 | **时间轴回放** | 你的 `radar_rank_history` 和 `radar_event_snapshots` **已经在存位次与每日快照**了——这是回放功能现成的燃料，不用新采集 |
| 9 | **区域预设 + URL 状态** | `?lat=&lon=&zoom=&layers=conflicts,bases` 可分享。原生 JS 十几行 |
| 10 | **地图点位聚类** | 点多了必卡，网格聚类（原型已实现，48 个航班簇）即可，不必引入 Supercluster |

### P2 —— 可以看，但别急着做

- 国家面板（点国家出简报 + 7 日时间线）
- 跨流关联（Convergence / Triangulation / Velocity Spike 等 14 类信号）
- 预测市场、直播摄像头、卫星轨道（CelesTrak TLE + SGP4）
- 昼夜分界线（**原型已实现**，纯本地计算，零成本）

### 明确不建议搬

| 东西 | 原因 |
|---|---|
| 双地图引擎（globe.gl + deck.gl） | 会引入 Three.js / MapLibre / deck.gl 三个重依赖，直接违背你「无 CDN、无构建、断网可用」的立身原则。**单引擎 SVG 或 Canvas 足够** |
| Tauri 桌面端、Redis 三层缓存、Protobuf、Vercel/Railway | 与你「单机、SQLite、零依赖」的定位冲突 |
| 6 个站点变体（world/tech/finance/…） | 你现在是多模块共用外壳，不需要拆站 |
| MCP 服务端 / 站点白标 | 工程量大且与本地定位无关 |

→ **我的建议：不要依赖它**。它自己也是从上面这些上游拿的数据，你直接对接上游更可控、更快、也没有 EULA 约束。

## 5. 「分主题区分国内外」——现状与我建议的设计

### 5.1 现状（读代码得出的结论）

**主题维度：有字段，但语义不是你要的那个。**

`core/radar/cluster.py:201` 先给 `category` 一个空串，紧接着 `core/radar/score.py:204` 会把它覆盖掉：

```python
event["category"] = topic or "综合"     # topic 来自 interest_score() 的兴趣匹配
```

所以 `category` **是有值的**——它是「这条事件命中了你配置的哪个兴趣主题」的标签，取值来自
`social_radar.json → interests.topics`（AI 与大模型 / 芯片与半导体 / 开源软件 / 国际科技公司 /
游戏与消费电子 / 国际新闻 / 中国科技发展与科研成果 / 产业竞争与经济事件），没命中就是 `综合`。

实测最新日报：12 个故事里 **11 个是 `综合`**，只有 1 个落到具体主题。也就是说：

- 它是**兴趣对齐**标签，不是**新闻主题**分类（没有「灾害/网络安全/财经/地缘」这些类别）；
- 它是「和我关心的对不对口」，不是「这条新闻是什么」；
- 它**完全不含地域信息**；
- `report.py` 也没拿它分栏——分栏靠的是下面的平台白名单。

**「国内外」现在是按平台名硬编码的**，`core/radar/report.py:238-260`：

```python
# 中文网络热点：平台名命中白名单
any(p in ("微博","百度","哔哩哔哩","今日头条","网易","知乎") for p in platforms)
# 国际热点：平台名命中另一个白名单
any(p in ("BBC","德国之声","Hacker News","TechCrunch","GDELT","Reddit","Bluesky") for p in platforms)
```

→ **这两个白名单是写死的**。你今天新加的 `newsnow` 聚合源（抖音/知乎/贴吧/华尔街见闻/财联社/澎湃/凤凰）、`AnySearch` 源，**都不会自动进入任何一个分栏**。这就是你想「分主题区分国内外」时真正卡住的地方。

**噪音也是同源问题。** `social_radar.json` 里 `filters.rules` 是 `[]`——关键词语法没启用。原型里我用你的真实数据跑了分类，结果 `地缘冲突` 分到了「杜兰特与福克斯爆发冲突」（体育）、`能源资源` 分到了「石油是怎样变成衣服的」（科普），这就是缺规则过滤的直接后果。

### 5.2 我建议的设计（重要：不要只用一个维度）

我的核心建议是：**「国内/国际」不是一个维度，是两个正交维度**，混在一起做必然别扭。

| 维度 | 取值 | 怎么判定 | 和现有字段的关系 |
|---|---|---|---|
| **议题地理** `region` | `cn` / `intl` / `unknown` | ① 地理编码命中 → 按国家判；② 未命中 → 按语言兜底（zh→cn） | **全新正交字段**，现在没有 |
| **来源语言** `lang` | `zh` / `en` / … | 源定义里就有 | 已有（`radar_items.language`） |
| **主题** `theme` | `ai` / `chip` / `money` / `geo` / `disaster` / `cyber` / `energy` / `other` | 关键词规则（`filters.rules`），可选 LLM 兜底 | **建议扩展现有 `category`**，而不是另起一个字段 |

关于主题，这里给两个选项：

- **方案甲（推荐，改动小）**：把 `interests.topics` 从「8 条自由文本」收敛成一个**闭合的主题表**，`category` 继续用它，只是不再有「综合」这个大杂烩兜底（改为落到 `other` 并标注「未分类」）。好处是同一个字段、同一套匹配逻辑，只是把语义收紧。
- **方案乙**：`category` 保留为「兴趣对齐」轴（用于打分与推送偏好），另加一个 `theme` 作为「新闻类别」轴。两个轴各有用途，但要多维护一套规则。

**我的建议是甲**：你的 `interests.topics` 里「AI 与大模型」「芯片与半导体」已经很接近主题分类了，把它补成闭合集合（加 灾害自然 / 网络安全 / 地缘冲突 / 财经市场 / 能源资源）比新开一个字段省事，也不会让 `score.py` 的 `interest` 打分逻辑失效。

这样能回答四个不同的问题：
- 「**国内媒体怎么报道国际事件**」→ `lang=zh AND region=intl`
- 「**国际媒体怎么报道中国**」→ `lang=en AND region=cn`
- 「**这个主题国内报了多少、国际报了多少**」→ 主题 × region 矩阵（**原型右上角就是这个**）
- 「**某个事件有没有进中文信息环境**」→ 你 `report.py` 里现在已经在算了（`chinese_coverage`），把它拉成一个正式字段

### 5.3 原型里已经把这套结构做出来了

右侧新闻栏有：

- **地域 tab**：全部 / 国内（108 条）/ 国际（23 条）
- **主题 chip**：8 个主题 + 计数
- **主题 × 地域矩阵**：一眼看出哪个主题是「国内热、国际冷」（真实数据：`地缘冲突` 国内 11 / 国际 10，`灾害自然` 国内 18 / 国际 3，`网络安全` 国内 3 / 国际 0）

这个矩阵本身就是一个很有价值的分析视角——它正好能喂给你项目的核心命题（**信息茧房**）。

## 6. 当前项目具体要改哪里

原则：**全部新增，不动现有逻辑**。每一步做完都可以单独验收，任何一步失败都不影响 GitHub 模块和雷达日报。

### 阶段 A：接入地图（**融入「每日热点」，不新增页面**）

设计原则：`web/radar.html` 的 **6 个 tab 一个不加**。地图成为 `#view-daily` 的画布，
并且**地图上的每个点 = `payload.highlights` 里的一条故事**（用 `story_id` 一一对应）。

| 文件 | 动作 | 内容 |
|---|---|---|
| `core/geo/__init__.py` | **新增** | 模块入口 |
| `core/geo/gazetteer.py` | **新增** | 地名库 + 匹配器。可从 GeoNames `cities1000` 或 Natural Earth `populated places` 生成；先做 500–2000 个词的版本就够用 |
| `core/geo/project.py` | **新增** | Web Mercator 投影（前端用同一套公式，保持同源） |
| `core/geo/centroid.py` | **新增** | **事件/故事的地理质心**：成员条目的加权质心，经度用圆均值防 ±180 回绕；命中 ≥2 个不同平台才算高置信。**这是「地图点 = 故事」的关键，也是 mockup 里已经验证过的那段算法** |
| `core/geo/sources.py` | **新增** | USGS / EONET / GDACS / OpenSky / Open-Meteo 五个适配器，走你现有的 `fetch.py` 超时+重试 |
| `core/radar/sources/__init__.py` | **改 1 处** | `SOURCES` 列表加 6–8 条 spec，`ADAPTERS` 分发表加 `"geo": geo.fetch`。**与你加 RSS 源的方式完全一样** |
| `core/radar/store.py` | **改** | ① `radar_events` 加 `geo_lon` / `geo_lat` / `geo_label` / `geo_hits` / `geo_confidence`（`_ensure_column` 已有）；② 新表 `radar_geo_points(layer, lon, lat, title, detail, source, observed_at, url, url_hash)` 存非新闻图层；③ `radar_events` 加 `region` 列 |
| `core/radar/cluster.py` | **改 ~5 行** | 建事件时调 `geo.centroid` 算坐标；故事继承代表事件的坐标 |
| `core/radar/score.py` | **改 1 行** | L204 的 `topic or "综合"` 改为落到闭合主题表（见 §5.3 方案甲） |

**mockup 里已经验证跑通的算法**（也就是阶段 A 要落到 `core/geo/` 的东西）：

- 事件地理质心：把故事各成员条目的坐标做加权质心，经度用圆均值防 ±180 回绕；
- 置信度分层：命中 ≥2 条来自不同平台的材料 → 高置信（实心菱形），只命中 1 条 → 低置信（虚线空心菱形，卡片上标「低置信」）；

- 同一套 `region`/`theme` 筛选同时驱动地图点位与故事卡。

**一个 mockup 才暴露出来的真实约束**：你的屏幕是 **1366×768**。
一张能显示到 ±60° 纬度的世界地图，高度约等于宽度的 **0.32 倍**（宽 1090px → 需 ≈350px），
所以地图放在顶部时，故事卡会落到首屏之外。mockup 里的应对：

- 三档高度：**收起 220px**（看分布）/ **默认 360px**（看全 ±60°）/ **展开 620px**（看全 ±85°）；
- **按视口高度自动选默认档**：`innerHeight < 860` 时默认「收起」档；
- 「图层」面板可折叠，折起后地图吃满整宽。

这三条都是真实尺寸驱动出来的决定，直接写进阶段 A 就行。

## 8. 风险与取舍（请重点看这几条）

1. **⚠️ 中国地图边界合规**：Natural Earth 的国界线表述在国内使用**存在合规风险**。如果这个地图要给别人看，中国部分必须换成**自然资源部标准地图**（`bzdt.ch.mnr.gov.cn`，免费下载，有审查号）。这一条比技术问题更重要。
2. **底图策略的两难**：World Monitor 用免 key 瓦片（OpenFreeMap/CARTO）——好看、有街道细节，但**需要联网**，会破坏你「断网也能显示核心界面」的承诺。原型选择了**内联矢量底图**（62 KB，断网可用，无街道细节）。建议：默认内联矢量，联网时可选叠加瓦片。
3. **AGPL**：见 §1。借鉴公式可以，复制源码文件不行。
4. **大陆网络**：Google News RSS 需代理；BBC 中文你已记录会被重置。所有需要代理的源都应显式标「需代理」。
5. **性能拐点**：SVG DOM 在 **≈2000 个点**以内没问题。超过就该换 Canvas 单层绘制（原型已是「点位先写 DOM、聚类层后叠」的结构，改造点很小）。
6. **反向风险——别过度采集**：图层一多，采集时长和失败面都会涨。你现在的熔断（连续 3 次降频 / 6 次停用）要覆盖到新源，且地图图层应允许**独立于日报**按更长间隔刷新（比如航班 1–2 分钟、灾害 10 分钟、静态层不动）。
7. **不编造**：这是你项目已经写在 README 里的原则，地图最容易破戒（位置错了看起来像真的）。**地理编码必须有置信度，未命中就留空**。
